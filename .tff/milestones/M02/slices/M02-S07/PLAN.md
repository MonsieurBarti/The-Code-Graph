# M02-S07: crates.io Release — Implementation Plan

> **For agentic workers:** Execute task-by-task with TDD. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `the-code-graph` and all workspace library crates to crates.io with automated release cycle via release-plz.

**Architecture:** All workspace crates get prefixed package names (`the-code-graph-*`) and shared metadata via `[workspace.package]`. Path deps include `version` for publish compatibility. release-plz automates Release PRs, version bumps, changelogs, and crates.io publishing. The existing `release.yml` handles binary builds and GitHub Releases only (no crates.io).

**Tech Stack:** Cargo workspace metadata, release-plz, GitHub Actions

## Spec Deviation

The original spec called for publishing only the binary crate with all library crates set to `publish = false`. This is not achievable because `cargo publish` requires all transitive dependencies to exist on crates.io. **Approved resolution:** All 7 library crates are published with `the-code-graph-` prefix (e.g., `the-code-graph-domain`). The `benches` crate remains `publish = false`. crates.io publishing is handled by release-plz (not `release.yml`).

**Modified acceptance criteria:**
- AC2 (original: all non-binary crates `publish = false`) → only `benches` has `publish = false`; all library crates are publishable with prefixed names
- AC7 (original: dry-run then publish single crate) → crates.io loop removed entirely; release-plz handles publishing; `release.yml` keeps only `--dry-run` safety check + GitHub Release

- [ ] **Step 1: Create `release-plz.toml`**

Write `release-plz.toml` at repo root:

```toml
[workspace]
# All publishable workspace crates are released together.
# Crates with `publish = false` (benches) are automatically skipped.
# Publish order is resolved from the dependency graph.
dependencies_update = true

# Use a single version tag so release.yml (triggers on v*) fires correctly.
# Default would be {name}-v{version} which does NOT match the v* glob.
git_tag_name = "v{version}"
```

- [ ] **Step 2: Create `.github/workflows/release-plz.yml`**

Write `.github/workflows/release-plz.yml`:

```yaml
name: Release-plz

on:
  push:
    branches: [main]

permissions:
  pull-requests: write
  contents: write

jobs:
  release-plz:
    name: Release-plz
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.RELEASE_TOKEN }}
      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
      - name: Cargo cache
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/registry
            ~/.cargo/git
            target
          key: ${{ runner.os }}-cargo-release-plz-${{ hashFiles('**/Cargo.lock') }}
      - name: Run release-plz
        uses: MarcoIeni/release-plz-action@v0.5
        env:
          GITHUB_TOKEN: ${{ secrets.RELEASE_TOKEN }}
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}
```

Uses `RELEASE_TOKEN` (PAT or GitHub App token) so that tag pushes by release-plz trigger the `release.yml` workflow. The default `GITHUB_TOKEN` cannot trigger other workflows.
